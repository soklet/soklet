# Soklet 4.0.0 remediation plan — October 4, 2026

## Recommendation

Finish the correctness and security work below before declaring 4.0.0 ready for publication. The review identifies real remaining implementation work. Prioritize shared root causes, with a small regression-driven change per slice, rather than treating its 201 catalog entries as 201 independent projects.

Most changes should stay inside existing implementations. A few items concern public contracts and need a separate API review before implementation; those are listed explicitly below.

**Status:** S1a–S1f, S2a–S2e, S3a–S3e, S4a–S4f, S5a–S5j and S6a–S6b implemented with local validation. Remaining S2 and S6 work, and S7–S10, are pending. Work is on the current branches. The user owns commits and pushes; changes remain unstaged unless staging is requested.

### Corrections to the review's suggested direction

1. **Disconnect behavior must be revision-specific.** Modern MCP says closing the SSE response stream cancels the request. The 2025 transport says disconnection should not itself mean cancellation. Preserve the latter and ordinary HTTP half-close behavior. See [modern cancellation](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http#cancellation) and [2025 transport rules](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#sending-messages-to-the-server).
2. **F225 is an urgent migration correction, not a reason to restore implicit hooks inside `awaitShutdown()`.** Use `SokletApplication` for a standalone process; a manually owned JVM hook must call blocking `close()` or join shutdown completion.
3. **F228 is principally a documentation correction.** Asynchronous, observational transition callbacks are an existing decision. Essential flushing belongs in bounded `ShutdownCleanup`; arbitrary observer code must not hold shutdown hostage.
4. **F274's client-IP allegation was narrowed by the report's own verifier.** Its trust policy requires the edge to sanitize forwarded families. Retain that requirement; independently evaluate the effective-origin selection and adapter divergence. Choosing X-Forwarded-For merely because it exists does not establish trust.
5. **F273's check-then-`toRealPath()` suggestion is incomplete.** A pathname can change between the symlink check and the open. Preserve the no-follow and root-containment guarantees while resolving aliases; do not claim race safety from that check alone.
6. **C008 concerns an API tradeoff.** Automatically aborting every admitted HTTP stream at quiesce would truncate finite downloads. Correct misleading cooperation prose immediately, then review an explicit graceful-stop policy/signal.
7. **Some “low” entries merit release fixes.** Parsing differentials, typed-number expansion, authorization checks, synchronous-publisher recursion and an unusable SSE transport SPI are more important than cosmetic severity labels suggest.
8. **Appendix A needs two exceptions to blanket deferral.** Recheck F027 against the 2025 rule requiring a message to use only one connected stream; a documented duplicate-delivery design does not settle conformance. Recheck F286's absolute-form authority handling while fixing F257. See [2025 multiple connections](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#multiple-connections) and [RFC 9112 request targets](https://www.rfc-editor.org/rfc/rfc9112.html#section-3.2).

### S1 — request parsing and security boundaries

Start with **S1a: F257, F258 and F259**. These are independently reproduced and can be addressed without expanding public API.

- Separate HTTP origin-form parsing from general URI authority parsing. Preserve every leading path component and the correct raw path, including repeated slashes. Verify ordinary absolute URLs, `OPTIONS *`, query extraction, dot-segment behavior, encoded-slash rejection and malformed UTF-8. Do not fix this by collapsing `//` into `/` or silently changing the decoded routing contract.
- Parse raw form pairs directly, rather than embedding form text into a URI. Preserve literal `#`, spaces and other legal form-value characters. Keep URL query validation distinct from form-body parsing.
- Parse Content-Type parameters with quote-aware rules, independent of ordering. Define duplicate/conflicting charset behavior and preserve strict charset decoding and fixed, redacted failures.
- Preserve duplicates and empty **values**. A bare `name` and `name=` remain one empty value; repeated empties remain multiple occurrences. Scalar binding continues to reject multiple occurrences before converting a single blank value to `Optional.empty()`.
- Proposed follow-up from the earlier parameter discussion: retain explicitly empty names (`=value`) under the empty-string key; distinguish them from separator-only gaps. Document the decision and test it. No new collection type or injection mode is needed.

Then split the remaining work into small changes:

- **Header occurrence model (F256):** recommend one List entry per physical field occurrence in every construction path. Keep comma parsing in field-specific consumers. A single `Accept-Encoding: gzip, deflate, br` should be one scalar field value; two actual occurrences remain two and still fail singular injection. Audit the existing split-field consumers, both servlet bridges and compression/CORS/localization before changing the helpers. Preserve empty field values where the field grammar allows them; never deduplicate duplicate authentication or framing fields.
- **Framing (F178, F179, F284, F205, F216):** bound incremental parser scanning, validate chunk extensions, reject unsupported HTTP/1.0 transfer encoding, reject bare CR in SSE handshakes, and sanitize rejected SSE response framing. Use the same security rules across HTTP and SSE, including duplicate Content-Length and CL+TE rejection. RFC 9112 requires a bare CR to be invalid or replaced with SP, not treated as an independent line terminator: [message parsing](https://www.rfc-editor.org/rfc/rfc9112.html#section-2.2).
- **Trusted proxy chain (C016, F274):** centralize adapter client-IP selection with core's right-to-left trusted-hop logic. Keep socket peer, forwarded origin and claimed client port as distinct concepts; `EffectiveClientIpResolver` returns an address, not an authenticated forwarded port. Do not pretend delegation alone fixes `getRemotePort()`. Define port behavior explicitly, and test forged leftmost entries, mixed families, malformed chains and untrusted peers in both adapters.
- **Static files (F273):** give resolvers a consistent file identity across case/alias spellings without enabling symlink escape. Verify case-insensitive APFS, case-sensitive paths, index files, root containment and link replacement; obtain Windows evidence for claims involving NTFS aliases. Do not add a general dot-file ban as an incidental fix.
- **HTTP representation/cache details (F275–F278):** reproduce compression/conditional ETag and Vary issues, then fix case-insensitive header handling and cache variation together. Do not remove a legitimate Content-Type from every HEAD or bodyless response indiscriminately.
- Recheck F286 while separating target forms: wire absolute-form authority must not be overridden by an unrelated Host header. Correcting this must retain the proxy-trust boundary for effective origin.

**Validation:** utility and binder regressions plus a small real-socket parser/route test. The physical path must use exact path assertions; `startsWith` cannot catch the lost-segment bug. Keep hostile input sizes small and hard bounded.

### S1d completed — authority, empty names and proxy trust (October 5)

- Absolute HTTP request targets replace the effective Host authority, retain their scheme for request-based origin resolution, and reject malformed authorities with fixed diagnostics. HTTP/1.1 physical Host validation remains before dispatch. Raw paths, query parameters and request copying retain their semantics. This implements reopened F286 ([RFC 9112 §3.2.2](https://www.rfc-editor.org/rfc/rfc9112.html#section-3.2.2)).

- Both servlet adapters delegate client address selection to core. Forwarded ports are selected from the same client entry; no port means zero, with socket fallback only when forwarding is unusable/untrusted (C016).
- Allowlisted origin resolution selects the nearest proxy's entry/values without reaching back into client-controlled entries for missing metadata. TRUST_ALL retains its established leftmost behavior. The requirement for trusted edges to sanitize both Forwarded families remains; the review's retracted cross-family client-IP claim is not reopened (F274).
- No public signatures changed. Targeted core checks passed on JDK 17 (123 executed; one SSE test requires JDK 21+) and JDK 25 (124 executed). The JDK 21 static-analysis clean compilation passed. Both servlet adapters passed 13 focused tests against the rebuilt development core JAR. Raw logs and the temporary Maven repository are outside source control.

### S1e/S1f completed — file identity and cache metadata (October 5)

- Independently reproduced the APFS alias defect against the development JAR: `.env` was hidden while `.ENV` was visible. No-follow resolution now obtains actual directory-entry spellings using file identity, without calling symlink-following real-path resolution on request paths. Explicit hard-link names remain separate policy paths; unsupported aliases fail closed. Link/file replacement by application resolvers is checked before response creation. This does not provide an atomic namespace snapshot through later path-backed delivery; docs disclose the stable-directory requirement. NTFS/Windows runtime qualification remains unperformed (F273).
- Default Content-Type is added only for a present body; explicit headers and HEAD representation metadata survive (F276).
- CORS controlled fields update case-insensitively and Vary token merging preserves wildcard and existing dimensions (F277). The List migration already prevented the reported complete Vary loss; the new reproducer confirmed contradictory duplicate Access-Control-Allow-Origin values from the same case-sensitive copy.
- Origin-dependent policies add Vary: Origin to allowed, denied and absent-Origin non-preflight variants, including missing-resource responses. Reject-all does not add it; arbitrary custom policies conservatively vary (F278).
- Compression-enabled 304 responses preserve Accept-Encoding variation without running a planner/codec/body provider (F275). Validator generation remains application-owned: the app must use the same weak semantic validator across identity/compressed variants, or coding-specific strong validators. Automatically weakening every bodyless validator was rejected because it cannot establish what an omitted representation would select. Weak If-Match rejection is required by the protocol, not a validator-comparison bug. User docs explain the supported pattern.
- F260 is closed as the existing documented malformed-header fallback contract; the regression now covers a valid range mixed with an invalid quality. Request Javadocs explicitly describe the combined-input fallback.
- F262 is closed with a documented interpretation limit: [HTML's algorithm](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#multipart/form-data-encoding-algorithm) escapes quotes/CR/LF without escaping literal percent text, so the inverse is ambiguous. Preserve literal quoted parameter spellings rather than silently aliasing distinct user-supplied names. The review itself retracts the filename-star precedence/entity-400 claims; RFC 6266 does not govern multipart form-data, and [RFC 7578 §4.2](https://www.rfc-editor.org/rfc/rfc7578.html#section-4.2) prohibits generating filename-star. No speculative multipart parser change was made.
- Four new cache regressions failed before correction. S1's 228 selected tests were exercised across bounded JDK 17/25 runs (one JDK 17 SSE skip; no JDK 25 skips), including the validator ownership clarification. No public signatures changed. Raw evidence stays outside Git.

### S2 — streaming internals

- Replace active `Object.wait` backpressure/start barriers with virtual-thread-friendly waits. Keep interruption, wakeup, queue ownership and notification ordering correct. Do not replace an entire monitor mechanically; preserve atomic state transitions. Cover both HTTP streaming and active MCP output channels.
- Reserve runnable producer capacity **before** committing a response head. On virtual-thread runtimes prefer per-task execution bounded by lifecycle admission; on JDK 17 use bounded platform execution with direct handoff or a bounded precommit wait/rejection. A stream waiting indefinitely behind another long-lived producer must not receive a misleading 200. Reject inline custom-executor execution safely and document the asynchronous executor requirement.
- Make precommit rejection and postcommit failure finish through one exactly-once lifecycle path. Report actual 503/failsafe status, release ownership/reservations, never invoke a rejected producer, and finish OTel spans. Cover streams returned without a Resource Method as well as normal routes.
- Propagate transport handoff failure instead of swallowing it while observers record success. Keep intended status, committed status and stream termination distinct. A producer failure after a valid head was committed still aborts the body; it cannot retroactively become a 500.
- Isolate application cancellation callbacks and termination observers from event loops, timeout threads and unrelated lifecycle-accounting work. Bound retained callback work; do not hide uncooperative residual work or release physical capacity while it still owns resources.
- Separate successful encoder-tail finalization from cancellation cleanup deadlines. A healthy, slow drain should complete; socket progress must prevent a false idle timeout after the writer returns. A genuinely stalled drain remains bounded.
- Avoid treating routine cancellation/interruption as an internal failure; retain meaningful cleanup diagnostics and actual resource-close errors.
- Trampoline synchronous `Flow.Publisher` demand, preserving one-at-a-time flow control without recursive stack growth or leaked lifetime accounting.
- For F068/F195, design a profile-aware response-disconnect policy. Modern MCP SSE closure cancels/fences its request; legacy POST SSE detaches the writer while session cancellation remains explicit. Preserve ordinary HTTP half-close/pipelining. Specify what happens to idle HTTP feeds with no next write; do not claim TCP distinguishes a full peer close from `shutdownOutput()`.

**Validation:** finite loopback tests for capacity rejection, custom executors, slow-but-progressing drain, stalled drain, encoder close, publisher reentrancy and races. Add a JDK 21 subprocess with a small constrained virtual scheduler so carrier exhaustion needs only a handful of sockets. Verify JDK 17/21/25 behavior. OTel rejection/termination tests must prove every span ends exactly once.

### S1c — bounded HTTP/SSE framing (F178/F179/F284/F205/F216)

Implemented on October 4–5, 2026:

- **F178:** the tokenizer caches its SPACE and CRLF delimiter searches at the current position. An incomplete delimiter search resumes at newly arrived bytes, retaining only the suffix that can straddle a read. The cache has two entries; movement, compaction and capture release preserve correct search state. The HTTP parser separately caps method tokens at 64 bytes and chunk-size lines, including extensions but excluding CRLF, at 8,192 bytes. Incomplete lines reject at the first over-limit byte; a split CRLF at the chunk-line limit remains valid. Capture regressions verify that a short malformed request line cannot borrow a separator or expose bytes from the following pipelined request.
- **F179:** HTTP/1.0 requests containing Transfer-Encoding fail as malformed framing before body parsing or resource-method dispatch. The response closes the connection, so a following pipelined request cannot run. Ordinary HTTP/1.0 Content-Length bodies and supported keep-alive parsing remain intact.
- **F284:** chunk sizes contain only hexadecimal digits. Extensions validate names and values against token/quoted-string syntax, including quoted pairs, supported SP/HTAB bad whitespace and obs-text inside quoted strings. Leading size whitespace, trailing size whitespace without an extension, invalid controls, bare CR/LF, unquoted obs-text and incomplete extension syntax reject. Valid extensions remain ignored when assembling the body. See [RFC 9112 chunk syntax](https://www.rfc-editor.org/rfc/rfc9112.html#section-7.1.1).
- **F205:** SSE parsing preserves the raw input until validation and rejects any bare CR instead of manufacturing a new header line. CRLF and the existing LF-only input support remain. Whitespace-only header lines now reject as folded input instead of hiding later fields. SSE Content-Length uses unsigned ASCII decimal syntax and requires exactly one zero-valued occurrence; signed zero, comma values, repeats and all Transfer-Encoding fields reject.
- **F216:** rejected and ordinary finite SSE responses discard application framing and hop-by-hop fields, including fields nominated by Connection. The transport emits one Connection: close and the actual finite body length, preserving bodyless-status restrictions. Other fields, repeated authentication challenges, cookies and Date remain. Accepted streaming-handshake behavior is unchanged.
- Updated HttpServer/SseHandshakeResult Javadocs, the migration guide, and website request, server-configuration and SSE documentation. No public types or signatures changed.

## Completion standard

The remediation is complete when verified release defects are fixed, design questions have an explicit reviewed resolution, public docs match the implemented supported profiles, and targeted/integration tests cover the corrected paths. Deferred items remain clearly disclosed. Publication readiness additionally requires final immutable-candidate validation after the user's final commits; this plan cannot substitute for those results.
